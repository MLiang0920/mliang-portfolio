开发故事

8 个真实的技术挑战

从踩坑到爬出，这是 0 到 1 路上每一个被解决的问题。

CHALLENGE 01

Tailwind CSS v3 / v4 版本冲突

同时安装了 v3 和 v4 导致 PostCSS 插件解析失败，构建报 "Unknown word use strict"。最终回退到 v3 标准的 @tailwind 指令 + .cjs 配置文件。

PostCSS CommonJS 版本管理
CHALLENGE 02

better-sqlite3 编译失败

native 依赖需要 ClangCL 工具集，本机缺失。评估后判断 SQLite 非必需，改用 JSON 文件存 chats，完全规避 native compile 问题。

Native module 架构权衡
CHALLENGE 03

ESM / CommonJS 混合困境

package.json 加 "type": "module" 后 Electron 主进程因 require 报错。把所有主进程文件改 .cjs 后缀（main.cjs / preload.cjs），让 ESM 与 CJS 共存。

Electron Node.js
CHALLENGE 04

file:// 协议下静态资源加载失败

打包后 src="/icon.png" 被解析为磁盘根目录。批量替换为 ./icon.png 相对路径，public/ 与 dist/ 同步同步资源。

Electron 资源路径
CHALLENGE 05

electron-builder 自动签名 bug

打包时把 PFX 密码替换成 sha256 hash，导致 signtool 报"PFX password not correct"。彻底禁用内置签名，写独立 sign-all.ps1 脚本，打包后用 signtool 手动签 win-unpacked + installer。

code signing PowerShell 解耦
CHALLENGE 06

winCodeSign 缓存解压失败

7z 解压 macOS 符号链接时报"客户端没有所需特权"。整个构建链改用管理员权限，封装 build-signed.ps1 自动 RunAs。

权限 符号链接
CHALLENGE 07

应用图标安装前后不一致

PNG 单分辨率被 Windows 强行采样导致失真。引入 sharp + png-to-ico 自动生成 16/32/48/64/128/256 六个分辨率合并为标准 .ico (361KB)，安装包/任务栏/快捷方式所有场景使用同一张。

图标设计 Sharp
CHALLENGE 08

Smart App Control 内核级拦截

Win 11 SAC 是内核级安全功能，自签名证书一律拦截，无"仍要运行"按钮。诚实告知用户技术天花板，提供四条合法路径：关 SAC / 买 EV 证书 / 上 Microsoft Store / 改 PWA 网页。这道题没有取巧的解法，只有正面认知与决策。

Windows 安全 权衡决策 PWA
