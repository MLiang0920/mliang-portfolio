一、项目最终想做成什么

这不是一个“抓点数据发个链接”的脚本，而是一个完整的游戏美术舆情播报产品： 从 B站 选题、微博补图与评论、AI 摘要与分析，到 H5 页面生成、EdgeOne 部署、企业微信图文卡片推送，全链路闭环。

B站热点抓取 微博热议补全 AI 标题与摘要 H5 详情页 EdgeOne 部署 企微 news 卡片

最终用户要求

  • 企微里点开的效果，必须和预览效果一致。
  • 详情页图片必须以原画、皮肤图、官方素材、游戏截图为主。
  • 不要真人 COS 图进入轮播图。
  • 三条推送要尽量是不同话题，不能全挤在同一个热点里。
  • 卡片封面要能稳定刷出来，别再出现“封面空白”。

二、当前稳定架构

push_news.py

负责抓取、AI 改写、HTML 生成；不再直接推消息。

weibo_fetcher.py

负责微博搜索、评论抓取、账号过滤、原画图源辅助。

pack_for_edgeone.py

负责资源本地化、HTML 文件名版本化、生成 zip 和 url_map.json。

push_edgeone.py

负责使用 EdgeOne 公网链接推送企微卡片，支持主群/测试群/自定义 webhook。

auto_push.py

负责把抓取、打包、部署、推送串成一键主流程。

三、从 0 到 1 的开发时间线（对话复刻版）

阶段 1：先做出最小可跑通版本

先把 B站 搜索、评论抓取、AI 改写、HTML 生成、企微推送这条最小链路打通，目标是先从“没有产品”变成“至少能发一版内容”。

阶段 2：H5 页面不断升级

页面逐步增加轮播图、玩家心声、AI 舆情分析师、风险提示、竞品对比，开始从“脚本产物”向“可交付页面”演化。

阶段 3：接微博，把原画质量拉上来

发现只靠 B站 截帧图质量不稳定，于是开始接微博高清原图和评论区玩家心声，让页面真正具备“美术舆情”味道。

阶段 4：部署到 EdgeOne Pages

内网地址在手机企微根本不可用，因此将详情页改为部署到 EdgeOne，形成公网访问链路。

阶段 5：缓存、鉴权、旧页错页的大排查

这是最反复的一段：用户看到的页面总和预览不一致。最终确认是 EdgeOne token 鉴权 + 企微路径缓存双重叠加问题。

阶段 6：版本化 HTML 名，稳定绕过缓存

pack_for_edgeone.py 在打包时直接把 HTML 改成带时分秒的新文件名，再由 push_edgeone.py 读取 url_map.json 推送，终于把缓存问题压住了。

阶段 7：真人 COS 图彻底成为显性需求

用户明确要求：哪怕微博正文来自 COS 博主的美术讨论，最终页面展示出来的也只能是原画、皮肤、官方图，不要真人画面。由此确定“图源白名单优先”的路线。

阶段 8：三主题、多封面、测试群/主群分离

项目开始向真正的软件整理：支持测试群推送，确保多主题内容，封面统一走 B站 CDN，避免企微抓不到图。

五、做错过的路线

误区 真人 COS 主要靠图像算法识别

这条路试过很多轮，最后还是放弃了。因为上半身立绘原画和真人 COS 在“有脸、有皮肤露出”这个维度上极其相似，算法很难稳定区分。

  • 试过 OpenCV Haar 人脸检测
  • 试过肤色占比、饱和度、颈部区域特征
  • 结果是：有些真人会漏掉，有些原画会误伤

正确 图源白名单优先

最终确定：决定图片质量和安全性的，不是图像识别算法，而是图源。只要来源足够可信，页面稳定性和观感就会高很多。

六、当前最靠谱的实践

  • 详情页图片：官方原画图优先，其次原画分享博主，再退回 B站 视频截图。
  • 卡片封面：统一用 B站 视频封面，保证企微能稳定抓图。
  • 详情页链接：必须使用 EdgeOne 带 token 的 URL。
  • 缓存策略：HTML 文件名版本化是第一优先级，query 参数只是辅助。
  • 发布策略：先发测试群，再发主群。
  • 脚本职责：生成、打包、部署、推送必须分层。

八、下一个 agent 接手时该怎么继续

  1. 先读《舆情播报记录.txt》和《上下文2.md》。
  2. 再重点阅读 push_news.py / weibo_fetcher.py / pack_for_edgeone.py / push_edgeone.py / auto_push.py。
  3. 先在测试群跑一遍：python auto_push.py --test。
  4. 重点验证三件事：三主题、三张不同封面、详情页无真人 COS。
  5. 后续优先重构 regen_html.py，再扩展不同游戏的关键词模板和白名单池。

九、这次项目的价值

这次做的不是一个“能跑的脚本”，而是一套经过真实用户反复验收、反复否定、反复修正后，逐步收敛出来的产品化流程。 它真正难的地方，不在技术点本身，而在于：缓存、鉴权、内容质量、图源策略、企微展示效果、用户感知结果，这些问题是一起缠在一块的。

所以，这份页面既是给下一个 agent 的接手文档，也是这个项目从混乱到成型的一份作品集过程页。
